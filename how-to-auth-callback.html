How DBH Authentication Works

A public explanation of the DBH authentication callback page and what happens after a supported authentication or account recovery flow returns to DBH.

Step-by-step guide

Use the instructions below to understand this DBH page and complete the relevant task safely.

01

Authentication starts

You begin from a DBH sign-in, registration or supported recovery flow.

02

The provider returns

If a supported authentication provider is used, the provider returns an authentication response to the DBH callback address.

03

DBH processes the response

The callback page is a transition point. The authentication script processes the returned session information.

04

A session is prepared

When the response is valid, the DBH application can establish the account session used by protected pages.

05

You continue to the dashboard

Successful authentication redirects the user to the authenticated DBH area.

06

Do not share tokens

Authentication tokens and recovery links are sensitive. Do not paste them into chats, emails or public posts.

07

If the page gets stuck

Return to the Sign In page and try again. If the problem continues, use the published DBH support contact.

08

Provider buttons are currently disabled

Google, Facebook, X, GitHub and GitLab remain disabled on the public authentication forms until their OAuth configuration is completed.
